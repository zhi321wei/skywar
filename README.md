# 苍穹战机 SkyWar

一款纵向卷轴空战射击手游（类似《雷电》系列），纯 Java + Canvas 实现，**零第三方依赖**，全部美术、音效、BGM 均由代码/脚本程序化生成。

> 当前版本：**1.8**（versionCode 9）

## 下载安装

- 仓库根目录 [`dist/SkyWar.apk`](dist/SkyWar.apk)（每次发版覆盖同一个文件）
- 或到 [Releases](../../releases) 下载对应版本

安装要求：Android 5.0（API 21）及以上，仅需竖屏，无需任何权限。

## 隐私

本游戏不收集任何个人信息，不申请任何系统权限（安装包未声明 `INTERNET` 权限，系统层面无法联网），无第三方 SDK、无广告、无内购。全部进度仅保存在本机应用私有目录，卸载即删除。详见[隐私政策](https://zhi321wei.github.io/skywar/privacy.html)。

## 玩法

| 模块 | 说明 |
| --- | --- |
| 出击作战 | 10 个关卡，每关含成波敌机 + 关底 BOSS。通关获得金币（首通有额外赏金），失败仅保留击杀收获 |
| 机库改造 | 三大页签：**主武器 / 超级武器 / 飞机配件**，消耗金币升级，可随时更换装备 |
| 补给商店 | 解锁新武器、新超级武器、双联火控挂架（永久解锁，无消耗品） |
| 战斗 | 单指拖动操控战机（自动开火），右下角超级武器按钮（能量满可释放，支持第二根手指触发） |

### 主武器
- **火神机炮**：高射速直射，升级增加并列炮管
- **脉冲激光**：可穿透多个目标，单点高伤
- **离子散射**：扇形弹幕，清理密集小型机
- **追猎导弹**：红外制导自动锁定最近目标，命中产生小范围爆炸溅射，升级增加齐射数量

### 双主武器 · 融合系统
在补给商店购买 **双联火控挂架** 后，可同时装备两把主武器（各自独立供弹、独立冷却），
并激活对应**融合效果**：主武器页点击卡片即可指定「主武器 / 副武器」。

| --- | --- | --- |
| 火神 + 火神 | 超载同频 | 射速 +25%，伤害 +10% |
| 火神 + 激光 | 贯穿弹幕 | 机炮弹获得穿透，射速 +10% |
| 火神 + 散射 | 霰射机炮 | 散射 +2 发，射速 +12% |

| 激光 + 散射 | 棱镜裂变 | 激光命中后炸裂 3 发散射弹 |
| 激光 + 导弹 | 相位猎手 | 导弹 +1 发，穿透 +1 |
| 散射 + 散射 | 弹幕饱和 | 散射 +3 发，射速 +10% |

## 版本号规则

每次更新 **versionName +0.1**（1.0 → 1.1 → 1.2 …），同时 **versionCode +1**，使用同一签名证书，
可直接覆盖安装旧版本，存档保留。

修改 `VERSION` 文件后执行 `bash build.sh` 即可：

```
versionName=1.8
versionCode=9
```

## 自行构建

依赖：JDK 17、Android SDK（build-tools 36 / platform android-36）。
不依赖 Gradle，构建脚本直接调用 `aapt2 → javac → d8 → zipalign → apksigner`。

```bash
bash build.sh          # 产出 dist/SkyWar-<version>.apk 与 dist/SkyWar.apk
```

辅助脚本（Python 3，需 Pillow）：

```bash
python tools/gen_icon.py    # 生成全部密度的启动图标
python tools/gen_audio.py   # 合成 10 个音效 + 20.6 秒循环 BGM（WAV）
```

## 工程结构

```
AndroidManifest.xml
res/                      图标、字符串、主题、raw 音频
src/com/zhiwei/skywar/
├── GameActivity.java     全屏竖屏 Activity
├── GameView.java         SurfaceView 游戏循环 + 虚拟坐标缩放 + 多点触控
├── Scene.java            场景基类
├── MenuScene.java        主菜单
├── StageScene.java       关卡选择 + 任务简报
├── HangarScene.java      机库改造
├── ShopScene.java        补给商店
├── BattleScene.java      战斗（敌机/BOSS/弹幕/粒子/超级武器）
├── ResultScene.java      结算
├── Art.java              全部美术资源（矢量绘制并烘焙为 Bitmap）
├── UI.java               面板/按钮/血条/金币等 UI 绘制
├── Backdrop.java         滚动星空 + 星云背景
├── Data.java             数值表：武器/超武/配件/关卡/花费/属性
├── Save.java             SharedPreferences(JSON) 存档
└── Sfx.java              SoundPool 音效 + MediaPlayer 背景音乐
```

渲染采用固定虚拟宽度 720、高度随屏幕比例自适应的坐标系，适配 16:9 ~ 21:9 各种机型。

### v1.6
- **修复敌方子弹偶尔变暗**：`Paint.setColor()` 带 alpha，会连带改掉画笔 alpha，而 `drawBitmap` 会把画笔 alpha 乘到图片上。战斗场景整帧共用一支画笔，星线（alpha 102）、玩家护盾环（alpha 136/51）、护盾机护罩、狙击机预警线这些半透明绘制完之后没有复位，紧随其后的敌弹就被画成了半透明
- 主绘制流程里每个分组（掉落物 / 敌机 / 玩家子弹 / 僚机 / 玩家 / 敌弹 / 粒子）之间都复位 alpha
- 敌机、玩家子弹、敌弹的循环体内 `drawBitmap` 前再复位一次，避免分组内互相污染
- 星线循环结束、首领机绘制前同样复位

### v1.5
- **渲染宿主从 `SurfaceView` 换成普通 `View`**：SurfaceView 的独立 Surface 在 buffer 协商、硬件画布、合成时序上都可能静默失败（进程活着、声音在放、屏幕全黑且不抛异常）。普通 View 的 `onDraw` 由 `ViewRootImpl` 逐帧驱动，与窗口同一条合成路径，不存在这类失败
- 删除 `surfaceCreated/surfaceChanged/surfaceDestroyed`、`lockCanvas`、`lockHardwareCanvas`、`unlockCanvasAndPost` 全部 Surface 调用
- 帧驱动改为 `postOnAnimation()` + `invalidate()`，update 与 draw 都在主线程
- 去掉 `clipRect(0,0,W,H)`：裁剪区一旦为空，之后所有绘制都会被丢弃，画面只剩纯黑
- **先出帧再烘焙**：第一帧先显示「初始化资源中…」，美术烘焙放到这一帧之后，启动不再有几百毫秒纯黑
- Activity 叠加独立提示层：首帧成功即隐藏；4 秒无任何一帧则显示红色诊断（含视图尺寸与版本号）
- 保留每帧复位共享画笔，继续压住「画面变透明」

### v1.4
- **回退渲染与启动路径到 v1.1**：撤掉 v1.2/v1.3 对渲染入口的改动（`setFormat`、硬件画布优先级、`softOnly` 降级、启动提示层），`src/` 回到实测能正常进入游戏的 v1.1 状态
- **重新修复画面变透明**：每帧统一复位 `Art` / `UI` / `Backdrop` 以及各场景的共享 `Paint`（`shader/alpha/style/strokeWidth/shadow`），杜绝上一帧状态串到下一帧
- 整屏铺底改用 `drawColor()` 覆盖整个画布，不再用 View 矩形，Surface 比 View 大时边缘不会漏
- `computeGeometry()` 以 `SurfaceHolder.getSurfaceFrame()` 尺寸为准，并加 NaN / 零尺寸兜底
- 屏幕震动时先铺不透明深空色并外扩 120px，边缘不露残影
- **BGM 移出主线程创建**（独立 `Looper` 线程），避免 `MediaPlayer.create()` 解析音频阻塞 `onCreate` 造成黑屏
